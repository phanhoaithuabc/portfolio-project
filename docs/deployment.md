# Portfolio Deployment

Run all build/operations commands from this project root. There is no dependency on another checkout. The root Jenkinsfile belongs to the future portfolio repository; configure SCM credentials and replace every `REPLACE_ME` repository URL in `deploy/argocd/portfolio.yaml` first.

## Images and CI

Build the API with `docker build --target runtime -t portfolio-api .` (or `--target test` for the CI integration image) and the web image with `docker build -f apps/portfolio/Dockerfile -t portfolio-web .`. Both build contexts are this directory. Bootstrap the controller as a rootful Podman Quadlet on port `127.0.0.1:8082` with `sudo bash scripts/bootstrap-jenkins.sh --apply` (`sudo podman exec portfolio-jenkins cat /var/jenkins_home/secrets/initialAdminPassword`), and register the unprivileged inbound builder with `sudo --preserve-env=JENKINS_AGENT_SECRET,JENKINS_URL,JENKINS_AGENT_NAME bash ci/jenkins/bootstrap-rootless-agent.sh --apply` (label `portfolio-rootless-builder`). On every build the pipeline runs npm tests/build/lint/`format:check`, Helm and Terraform checks, disposable PostgreSQL integration, and strict `npm audit` plus Trivy (including unfixed HIGH/CRITICAL findings). On `main` only, it publishes immutable SHA tags, resolves manifest digests, signs/attests with Cosign, verifies signatures/SBOM/provenance, and opens an `automation/portfolio-*` pull request updating `deploy/gitops/portfolio/images.yaml` with `repo@sha256` digests; it never pushes directly to `main`. Operator credential IDs are `portfolio-registry-push`, `gitops-push`, `cosign-signing-key`, `cosign-key-password` and `cosign-public-key`; create them in Jenkins, not source.

## Database and Storage

Use either [native PostgreSQL](native-postgres.md) on port 5433 or the `portfolio-db` legacy chart in namespace `portfolio-data`. Create the namespaced `portfolio-runtime` Secret using a protected operator file containing `PORTFOLIO_DATABASE_URL`, `PORTFOLIO_SESSION_SECRET`, `PORTFOLIO_ADMIN_USERNAME`, `PORTFOLIO_ADMIN_PASSWORD_HASH`, and optional editor credentials, or enable `externalSecrets.enabled: true` and `externalSecrets.runtimeKey` after running `sudo INSTALL_EXTERNAL_SECRETS=true bash ops/native/bootstrap-platform.sh --apply`. Follow [Studio Setup](portfolio.md) to generate hashes privately. The migration hook records applied SQL files and SHA-256 checksums in `portfolio_schema_migrations` under a PostgreSQL advisory lock without reseeding edited content.

The chart supports an opt-in private S3-compatible media bucket using `media.s3Bucket`, `media.s3Region` and `media.s3Prefix`; use `media.s3Endpoint` only for an S3-compatible service. When `media.s3Bucket` is empty, the API stores uploads on the mounted `portfolio-media` PVC (`helm.sh/resource-policy: keep`, `Prune=false,Delete=false`); when set, the chart also renders egress rules allowing HTTPS and IMDSv2 (`169.254.169.254/32:80`) so the API can use the node IAM role. On a shared EC2 host, provision the bucket and attach its prefix-scoped policy to the host's `node_role_name` using the standalone `infra/aws-media` Terraform root (plus `pod_instance_credentials = true` on the host root). Do not put access keys in Helm values or Kubernetes Secrets. Keep bucket public access blocked, enable encryption/versioning and require TLS. The API serves media through stable `/media/...` URLs, so the bucket itself need not be public. The `portfolio-media` PVC stays mounted through cutover to protect rollback and migration data. Run `npm run portfolio:media:migrate` for a dry run, then `npm run portfolio:media:migrate -- --apply` from a process that can read the mounted upload directory and write to the bucket; verify images before changing backup policy. Keep the bucket and database backups off-node. The chart enforces the expected database hostname, labels namespaces with Pod Security Admission (`restricted` on `portfolio`), sets Traefik `externalTrafficPolicy: Local` to preserve client IPs, and uses secure cookies behind the documented proxy chain.

## Rollout

1. Prepare k3s/Traefik, Helm, namespaces, private registry access and database connectivity. Optional platform/Terraform helpers are local to this project; they create no cloud resources unless explicitly applied.
2. Configure runtime/admin secrets, TLS and image references. Preview the native bootstrap with `bash ops/native/bootstrap-platform.sh`; use `--apply` only on a reviewed server.
3. Configure the repository URL and apply `deploy/argocd/portfolio.yaml` only after images, database, migrations and secrets are ready.
4. Verify readiness, project pages, language switch, contact form, admin login, draft privacy, content conflicts, uploads and persistent restart behavior.
5. Test off-node backup/restore and database rollback before relying on the service.

See [DNS/HTTPS](domain-pavietnam.md), [Capacity](ec2-sizing.md), [Operations](runbooks/incidents.md), and [Verification](verification.md). No infrastructure, DNS, credentials, or Git repository was provisioned during the project split.
